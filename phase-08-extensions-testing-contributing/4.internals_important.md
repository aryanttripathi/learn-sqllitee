# Phase 8 — Reference: Extensions, Testing, Contributing

---

## 1. The five extension seams

| Seam | API | Replaces / augments | Cost when unused |
|---|---|---|---|
| SQL functions | `sqlite3_create_function_v2`, `sqlite3_create_window_function` | an entry in a hash table | one lookup at prepare time |
| Collations | `sqlite3_create_collation_v2`, `sqlite3_collation_needed` | a `memcmp` | none |
| Virtual tables | `sqlite3_create_module_v2` | the b-tree, for one table | none |
| VFS | `sqlite3_vfs_register` | `os_unix.c` | one indirect call per I/O |
| Hooks | `sqlite3_set_authorizer`, `_trace_v2`, `_update_hook`, … | nothing | one NULL check |

Every shipped extension — FTS5, R-Tree, JSON, session, `dbstat`, `bytecode()` — is built
from exactly these. There is no private back door.

## 2. Loadable extensions

```c
#include "sqlite3ext.h"
SQLITE_EXTENSION_INIT1          /* declares the static API-pointer */

...your code, calling sqlite3_xxx() normally...

#ifdef _WIN32
__declspec(dllexport)
#endif
int sqlite3_myext_init(sqlite3 *db, char **pzErrMsg,
                       const sqlite3_api_routines *pApi){
  SQLITE_EXTENSION_INIT2(pApi);     /* wires every sqlite3_ call to the host */
  return sqlite3_create_module(db, "myext", &myModule, 0);
}
```

**What `INIT1`/`INIT2` actually do:** in an extension build, `sqlite3ext.h` `#define`s
every public API name to a field of a function-pointer struct
(`sqlite3_create_module` → `sqlite3_api->create_module`). `INIT1` declares the static
pointer; `INIT2` assigns it from the host. That is why a loadable extension links against
**nothing** and works with any compatible SQLite build.

```sh
cc -fPIC -shared -I<amalg-dir> -o myext.dylib myext.c     # .so on Linux
```
```sql
.load ./myext                     -- entry point inferred from the BASENAME
SELECT load_extension('./myext', 'sqlite3_myext_init');
```
```c
sqlite3_enable_load_extension(db, 1);
sqlite3_load_extension(db, "./myext", 0, &zErr);
sqlite3_auto_extension(xInit);    /* register for EVERY new connection */
```

| Return | Meaning |
|---|---|
| `SQLITE_OK` | loaded; unloaded when the connection closes |
| `SQLITE_OK_LOAD_PERMANENTLY` | keep the shared library loaded after the connection closes |

**Gotcha:** you cannot call any SQLite API before `SQLITE_EXTENSION_INIT2` runs — the
pointer is NULL. Crashes in extension init are almost always this.

Apple's system `/usr/bin/sqlite3` is built **without** extension loading. Build your own
shell from the amalgamation.

## 3. SQL functions

```c
int sqlite3_create_function_v2(
  sqlite3 *db, const char *zName, int nArg, int eTextRep, void *pApp,
  void (*xFunc)(sqlite3_context*,int,sqlite3_value**),
  void (*xStep)(sqlite3_context*,int,sqlite3_value**),
  void (*xFinal)(sqlite3_context*),
  void (*xDestroy)(void*)
);
int sqlite3_create_window_function(
  sqlite3*, const char*, int nArg, int eTextRep, void*,
  xStep, xFinal, xValue, xInverse, xDestroy
);
```

`nArg = -1` means "any number of arguments".

### 3.1 `eTextRep` flags

| Flag | Effect |
|---|---|
| `SQLITE_UTF8` / `SQLITE_UTF16LE` / `SQLITE_UTF16BE` / `SQLITE_UTF16` | preferred text encoding |
| `SQLITE_DETERMINISTIC` | same args ⇒ same result. Enables `OP_PureFunc`, hoisting out of loops, and use in index expressions and partial-index WHERE clauses |
| `SQLITE_INNOCUOUS` | safe to call from triggers/views in an untrusted schema |
| `SQLITE_DIRECTONLY` | **may not** be called from triggers or views — a security boundary |
| `SQLITE_SUBTYPE` | the function inspects argument subtypes |
| `SQLITE_RESULT_SUBTYPE` | the function sets a result subtype |

**Use `SQLITE_DIRECTONLY` for anything with side effects.** A hostile database file can
contain a view or trigger; without this flag, merely *opening* it could invoke your
function.

### 3.2 In-function API

```c
/* reading arguments */
sqlite3_value_type/numeric_type(v)          /* SQLITE_INTEGER|FLOAT|TEXT|BLOB|NULL */
sqlite3_value_int/int64/double/text/text16/blob/bytes(v)
sqlite3_value_nochange(v)                   /* UPDATE: this column is unchanged */
sqlite3_value_frombind(v)                   /* came from sqlite3_bind_* */
sqlite3_value_pointer(v, "type-tag")        /* the carray pattern */
sqlite3_value_subtype(v)

/* returning */
sqlite3_result_int/int64/double/null/text/blob/zeroblob/value/pointer/subtype(ctx, ...)
sqlite3_result_error(ctx, "msg", -1);  sqlite3_result_error_code/_nomem/_toobig

/* state */
sqlite3_aggregate_context(ctx, nBytes)      /* zeroed on first call; NULL on OOM */
sqlite3_user_data(ctx)                      /* the pApp pointer */
sqlite3_context_db_handle(ctx)
sqlite3_get_auxdata(ctx, N) / sqlite3_set_auxdata(ctx, N, p, xDelete)
```

`set_auxdata` caches per-argument work — a compiled regex, a parsed JSON path — across the
rows of one statement. It is the difference between recompiling a regex a million times and
once.

## 4. Virtual tables

### 4.1 `sqlite3_module`

```c
struct sqlite3_module {
  int iVersion;                      /* 1, 2, 3 or 4 */
  int (*xCreate)(sqlite3*, void *pAux, int argc, const char *const*argv,
                 sqlite3_vtab **ppVTab, char **pzErr);
  int (*xConnect)(...);              /* same signature */
  int (*xBestIndex)(sqlite3_vtab*, sqlite3_index_info*);
  int (*xDisconnect)(sqlite3_vtab*);
  int (*xDestroy)(sqlite3_vtab*);
  int (*xOpen)(sqlite3_vtab*, sqlite3_vtab_cursor**);
  int (*xClose)(sqlite3_vtab_cursor*);
  int (*xFilter)(sqlite3_vtab_cursor*, int idxNum, const char *idxStr,
                 int argc, sqlite3_value **argv);
  int (*xNext)(sqlite3_vtab_cursor*);
  int (*xEof)(sqlite3_vtab_cursor*);
  int (*xColumn)(sqlite3_vtab_cursor*, sqlite3_context*, int N);
  int (*xRowid)(sqlite3_vtab_cursor*, sqlite3_int64 *pRowid);
  int (*xUpdate)(sqlite3_vtab*, int argc, sqlite3_value **argv, sqlite3_int64*);
  int (*xBegin)(sqlite3_vtab*);
  int (*xSync)(sqlite3_vtab*);
  int (*xCommit)(sqlite3_vtab*);
  int (*xRollback)(sqlite3_vtab*);
  int (*xFindFunction)(sqlite3_vtab*, int nArg, const char *zName,
                       void (**pxFunc)(sqlite3_context*,int,sqlite3_value**), void **ppArg);
  int (*xRename)(sqlite3_vtab*, const char *zNew);
  /* v2 */ int (*xSavepoint)(sqlite3_vtab*,int);
           int (*xRelease)(sqlite3_vtab*,int);
           int (*xRollbackTo)(sqlite3_vtab*,int);
  /* v3 */ int (*xShadowName)(const char*);
  /* v4 */ int (*xIntegrity)(sqlite3_vtab*, const char*, const char*, int, char**);
};
```

| Method | Required? | Notes |
|---|---|---|
| `xCreate` | for `CREATE VIRTUAL TABLE` | **0 (or == `xConnect`) makes the table EPONYMOUS** |
| `xConnect` | yes | must call `sqlite3_declare_vtab()` |
| `xBestIndex` | yes | the planner interface |
| `xDisconnect` | yes | free the vtab object |
| `xDestroy` | if `xCreate` | drop persistent storage |
| `xOpen`/`xClose`/`xFilter`/`xNext`/`xEof`/`xColumn`/`xRowid` | yes | the cursor |
| `xUpdate` | writable tables | `argc==1` ⇒ DELETE; `argv[1]==NULL` ⇒ INSERT; else UPDATE |
| `xBegin`/`xSync`/`xCommit`/`xRollback` | transactional tables | |
| `xFindFunction` | optional | overload functions (e.g. `MATCH`) for this table |
| `xShadowName` | iVersion ≥ 3 | lets defensive mode protect your shadow tables |
| `xIntegrity` | iVersion ≥ 4 | participate in `PRAGMA integrity_check` |

### 4.2 `sqlite3_index_info` — the `xBestIndex` contract

```c
struct sqlite3_index_info {
  /* INPUTS */
  int nConstraint;
  struct sqlite3_index_constraint {
    int iColumn;              /* column index; -1 = rowid */
    unsigned char op;         /* SQLITE_INDEX_CONSTRAINT_* */
    unsigned char usable;     /* 0 ⇒ the value is NOT available in this join order */
    int iTermOffset;
  } *aConstraint;
  int nOrderBy;
  struct sqlite3_index_orderby { int iColumn; unsigned char desc; } *aOrderBy;
  /* OUTPUTS */
  struct sqlite3_index_constraint_usage {
    int argvIndex;            /* 1-based position in xFilter's argv[] */
    unsigned char omit;       /* 1 ⇒ SQLite will NOT re-check this constraint */
  } *aConstraintUsage;
  int idxNum;                 /* your plan id, passed to xFilter */
  char *idxStr; int needToFreeIdxStr;
  int orderByConsumed;        /* 1 ⇒ I produce rows in the requested order */
  double estimatedCost;
  sqlite3_int64 estimatedRows;     /* iVersion ≥ 2 */
  int idxFlags;                    /* SQLITE_INDEX_SCAN_UNIQUE */
  sqlite3_uint64 colUsed;          /* which columns the query needs */
};
```

Constraint operators:
```
SQLITE_INDEX_CONSTRAINT_EQ         2     _GT  4   _LE  8   _LT 16   _GE 32
SQLITE_INDEX_CONSTRAINT_MATCH     64
SQLITE_INDEX_CONSTRAINT_LIKE      65     _GLOB 66   _REGEXP 67
SQLITE_INDEX_CONSTRAINT_NE        68     _ISNOT 69  _ISNOTNULL 70
SQLITE_INDEX_CONSTRAINT_ISNULL    71     _IS 72
SQLITE_INDEX_CONSTRAINT_LIMIT     73     _OFFSET 74
SQLITE_INDEX_CONSTRAINT_FUNCTION 150+
```

### 4.3 The `xBestIndex` rules

```
1. SKIP any constraint with usable == 0.
2. To consume a constraint: aConstraintUsage[i].argvIndex = k  (1-based, your order).
3. omit = 1 is a PROMISE that you fully enforce it. Lying returns WRONG ROWS, no error.
4. orderByConsumed = 1 is a PROMISE about row order. Lying returns wrong order, no error.
5. estimatedCost competes with real b-tree costs — return a huge value for plans you
   do not want (that is how an unbounded scan is refused).
6. estimatedRows drives outer/inner loop choice.
7. Returning SQLITE_CONSTRAINT means "this join order is impossible for me" — the
   planner tries another. Use it when a needed constraint has usable == 0.
8. colUsed lets you skip computing columns nobody asked for.
9. xBestIndex is called MANY times, once per candidate join order. Keep it cheap and
   side-effect free.
```

Helper APIs available inside `xBestIndex`:
```c
sqlite3_vtab_distinct(pIdxInfo)        /* 0..3: how much de-duplication is wanted */
sqlite3_vtab_in(pIdxInfo, i, handle)   /* handle an IN(...) constraint yourself */
sqlite3_vtab_rhs_value(pIdxInfo, i, &pVal)   /* the constraint's right-hand value */
sqlite3_vtab_collation(pIdxInfo, i)
sqlite3_vtab_nochange(ctx)             /* inside xColumn during an UPDATE */
sqlite3_vtab_on_conflict(db)           /* inside xUpdate */
sqlite3_vtab_config(db, SQLITE_VTAB_INNOCUOUS | _DIRECTONLY | _CONSTRAINT_SUPPORT |
                        _USES_ALL_SCHEMAS)
```

### 4.4 Eponymous tables and table-valued functions

```c
static sqlite3_module mod = { 0, /*xCreate*/0, myConnect, myBestIndex, ... };
```
`xCreate == 0` ⇒ usable by name with no `CREATE VIRTUAL TABLE`. Declare HIDDEN columns and
they become function-style arguments:

```sql
sqlite3_declare_vtab(db, "CREATE TABLE x(value INTEGER, start HIDDEN, stop HIDDEN)");
SELECT value FROM myseries(1,10);        -- identical to:
SELECT value FROM myseries WHERE start=1 AND stop=10;
```

`EXPLAIN QUERY PLAN` echoes your plan id back:
```
`--SCAN myseries VIRTUAL TABLE INDEX 7:
                                    └ your idxNum
```

### 4.5 Common vtab bugs

1. `sqlite3_vtab` / `sqlite3_vtab_cursor` not the **first** struct member.
2. `omit = 1` without enforcing the constraint ⇒ silent wrong answers.
3. `orderByConsumed = 1` without producing that order ⇒ silent wrong order.
4. Forgetting `sqlite3_declare_vtab()` in `xConnect`.
5. A small `estimatedCost` for an unbounded scan ⇒ catastrophic join plans.
6. Allocating with `malloc` instead of `sqlite3_malloc`; `pVtab->zErrMsg` **must** come
   from `sqlite3_mprintf`.
7. Assuming `xFilter` is called once — it is called per outer-loop row in a join.
8. Side effects in `xBestIndex`.

## 5. Shadow tables

```sql
CREATE VIRTUAL TABLE docs USING fts5(title, body);
SELECT name FROM sqlite_schema;
```
Verified output:
```
docs           -- the virtual table
docs_data      -- real b-tree: inverted-index segments
docs_idx       -- real b-tree: segment directory
docs_content   -- real b-tree: the original rows
docs_docsize   -- real b-tree
docs_config    -- real b-tree
```

**"Virtual" means "the rows come from code", not "nothing is stored."** FTS5 and R-Tree
inherit ACID, backup, and `VACUUM` for free by storing everything in ordinary b-trees.

`xShadowName` + `SQLITE_DBCONFIG_DEFENSIVE` stop an attacker-supplied database from writing
hostile bytes directly into `docs_data`.

## 6. Hooks and the security surface

```c
sqlite3_set_authorizer(db, xAuth, pArg);      /* called at PREPARE time, per action */
sqlite3_trace_v2(db, SQLITE_TRACE_STMT|PROFILE|ROW|CLOSE, xTrace, pArg);
sqlite3_progress_handler(db, nOps, xProgress, pArg);   /* non-zero ⇒ interrupt */
sqlite3_commit_hook(db, xCommit, pArg);       /* non-zero ⇒ convert COMMIT to ROLLBACK */
sqlite3_rollback_hook(db, xRollback, pArg);
sqlite3_update_hook(db, xUpdate, pArg);       /* INSERT/UPDATE/DELETE row events */
sqlite3_preupdate_hook(db, xPreUpdate, pArg); /* needs SQLITE_ENABLE_PREUPDATE_HOOK */
sqlite3_wal_hook(db, xWal, pArg);
sqlite3_collation_needed(db, pArg, xCollNeeded);
sqlite3_interrupt(db);                        /* thread-safe cancel */
```

### 6.1 Authorizer action codes (selection)

```
SQLITE_CREATE_TABLE   SQLITE_CREATE_INDEX   SQLITE_CREATE_TRIGGER  SQLITE_CREATE_VIEW
SQLITE_DROP_TABLE     SQLITE_DROP_INDEX     SQLITE_DROP_TRIGGER    SQLITE_DROP_VIEW
SQLITE_INSERT         SQLITE_UPDATE         SQLITE_DELETE          SQLITE_SELECT
SQLITE_READ           /* PER COLUMN: arg1 = table, arg2 = column */
SQLITE_FUNCTION       /* arg2 = function name */
SQLITE_PRAGMA         SQLITE_ATTACH         SQLITE_DETACH
SQLITE_TRANSACTION    SQLITE_SAVEPOINT      SQLITE_RECURSIVE
SQLITE_ALTER_TABLE    SQLITE_REINDEX        SQLITE_ANALYZE
```

Return values:

| Return | Effect |
|---|---|
| `SQLITE_OK` | allow |
| `SQLITE_DENY` | the whole statement fails to prepare |
| `SQLITE_IGNORE` | for `SQLITE_READ`: the column reads as **NULL**; for others: the action is a no-op |

`SQLITE_IGNORE` on `SQLITE_READ` is the clean way to implement column-level redaction.

### 6.2 Hardening an untrusted database

```c
sqlite3_db_config(db, SQLITE_DBCONFIG_DEFENSIVE, 1, 0);       /* no writable_schema,
                                                                 no direct shadow writes */
sqlite3_db_config(db, SQLITE_DBCONFIG_TRUSTED_SCHEMA, 0, 0);  /* the schema may not call
                                                                 non-innocuous functions */
sqlite3_db_config(db, SQLITE_DBCONFIG_DQS_DML, 0, 0);
sqlite3_db_config(db, SQLITE_DBCONFIG_DQS_DDL, 0, 0);
sqlite3_db_config(db, SQLITE_DBCONFIG_ENABLE_TRIGGER, 0, 0);
sqlite3_db_config(db, SQLITE_DBCONFIG_ENABLE_VIEW, 0, 0);
sqlite3_limit(db, SQLITE_LIMIT_LENGTH, 1000000);
sqlite3_limit(db, SQLITE_LIMIT_SQL_LENGTH, 100000);
sqlite3_progress_handler(db, 10000, xInterrupt, 0);
sqlite3_set_authorizer(db, xAuth, 0);
```
```sql
PRAGMA trusted_schema=OFF;
PRAGMA query_only=ON;
```
That set is the standard configuration for opening a `.db` file you did not create.

## 7. The shipped extensions

| Extension | Size | What to learn from it |
|---|---|---|
| `ext/misc/series.c` | ~350 | the reference minimal vtab; hidden columns |
| `ext/misc/carray.c` | ~250 | `sqlite3_bind_pointer` — passing C arrays into SQL safely |
| `ext/misc/regexp.c` | ~700 | `auxdata` caching of a compiled pattern |
| `ext/misc/csv.c` | ~900 | a vtab over a file; `xCreate` arguments; schema inference |
| `src/dbstat.c` | ~800 | a real `xBestIndex`, including refusing a join order |
| `ext/rtree/rtree.c` | ~4,500 | an R-tree stored in a shadow table |
| `ext/fts5/` | ~28,000 | an LSM inverted index |
| `ext/session/` | ~6,600 | changesets, built on `preupdate_hook` |
| `ext/rbu/` | ~5,500 | resumable bulk update |
| `ext/expert/` | — | an index recommender using the planner itself |

### 7.1 FTS5 file layout

| File | Responsibility |
|---|---|
| `fts5_main.c` | the vtab interface, `MATCH`, `bm25`, `highlight`, `snippet` |
| `fts5_expr.c` | the MATCH query language parser |
| `fts5_index.c` | the inverted index: segments, doclists, merging |
| `fts5_storage.c` | the content/config shadow tables |
| `fts5_tokenize.c` | `unicode61`, `porter`, `ascii`, `trigram` |
| `fts5_hash.c` | the in-memory pending-terms hash |

Data model: `term → doclist = [(rowid, [positions]), ...]`, delta-encoded varints, stored
in **segments** that merge in levels like an LSM tree, all inside ordinary b-trees.

### 7.2 R-Tree

`%_node` (a BLOB per node), `%_rowid` (rowid → leaf), `%_parent` (node → parent).
`xBestIndex` reports a low cost for bounding-box constraints and encodes them into
`idxStr`; `xFilter` prunes subtrees whose box cannot match.

### 8.1 Writing a test

```tcl
set testdir [file dirname $argv0]
source $testdir/tester.tcl
set testprefix mytest

do_execsql_test  1.0 { CREATE TABLE t1(a,b); INSERT INTO t1 VALUES(1,2); }  {}
do_execsql_test  1.1 { SELECT * FROM t1; }                                  {1 2}
do_catchsql_test 1.2 { SELECT * FROM nosuch; }   {1 {no such table: nosuch}}
do_test          1.3 { expr {2*2} }              {4}
ifcapable fts5 { ... }
reset_db
finish_test
```

Result-matching patterns — this is how you assert on **query plans**:
```tcl
{/SCAN/}     the result MUST match this regex
{~/SCAN/}    the result must NOT match this regex
```

Corruption tests use:
```tcl
hexio_write $file $offset $hexdata
sqlite3_test_control SQLITE_TESTCTRL_IMPOSTER db main 1 $rootpage
```

### 8.2 Test controls you can use

```c
sqlite3_test_control(SQLITE_TESTCTRL_FAULT_INSTALL, xCallback);
sqlite3_test_control(SQLITE_TESTCTRL_OPTIMIZATIONS, db, mask);   /* 1 bit = DISABLE */
sqlite3_test_control(SQLITE_TESTCTRL_IMPOSTER, db, "main", onOff, tnum);
sqlite3_test_control(SQLITE_TESTCTRL_PRNG_SEED, seed, db);
sqlite3_test_control(SQLITE_TESTCTRL_ALWAYS, x);
sqlite3_test_control(SQLITE_TESTCTRL_ASSERT, x);
sqlite3_test_control(SQLITE_TESTCTRL_LOCALTIME_FAULT, onoff);
sqlite3_test_control(SQLITE_TESTCTRL_SEEK_COUNT, db, &n);   /* b-tree seeks */
sqlite3_test_control(SQLITE_TESTCTRL_BENIGN_MALLOC_HOOKS, xBegin, xEnd);
```

| Control | Why it is interesting |
|---|---|
| `IMPOSTER` | declare a **fake schema over a real root page** so a test can write deliberately invalid b-tree content |
| `OPTIMIZATIONS` | disable one optimization at a time — how you *measure* what each is worth, and how the project proves each is individually correct |
| `SEEK_COUNT` | assert an algorithm did not regress, in a test |
| `FAULT_INSTALL` | drive OOM and I/O-error injection from your own harness |

### 8.3 Coverage archaeology — the best first contribution

```sh
../configure --enable-debug CFLAGS="-g -O0 -fprofile-arcs -ftest-coverage"
make testfixture && ./testfixture ../test/select1.test
gcov sqlite3.c | tail
grep -n "#####" sqlite3.c.gcov | head -40      # lines never executed
```

write that test. The technique transfers to every project you will ever work on.

## 10. Invariants and gotchas

1. `sqlite3_vtab` and `sqlite3_vtab_cursor` **must be the first member** of your structs.
2. `pVtab->zErrMsg` must be allocated with `sqlite3_mprintf`; SQLite frees it.
3. Never call a SQLite API before `SQLITE_EXTENSION_INIT2`.
4. `xBestIndex` may be called many times per query — cheap and side-effect free.
5. `omit` and `orderByConsumed` are promises; breaking them yields wrong answers silently.
6. `xFilter` restarts the scan; do not assume it runs once.
7. Modules are per-connection; use `sqlite3_auto_extension` for all connections.
8. `SQLITE_DIRECTONLY` on every function with side effects.
9. Shadow tables are writable unless `DEFENSIVE` mode is on — declare `xShadowName`.
10. `sqlite3_create_module_v2`'s destructor runs when the **connection** closes.
11. A virtual table participates in transactions only if it implements
    `xBegin`/`xSync`/`xCommit`/`xRollback`.
12. Apple's system `sqlite3` cannot `.load`; build your own shell.
